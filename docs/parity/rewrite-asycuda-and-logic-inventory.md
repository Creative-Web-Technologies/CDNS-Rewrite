# Rewrite ASYCUDA & Logic Inventory

Read-only audit of what the **rewrite** (CDNS-Rewrite, `backend/src`) actually implements
for each parity unit, with `file:line` evidence, so it can be compared line-by-line against
the legacy system. eReg sync/validation is **excluded** by scope.

Status legend: **SAME-LOGIC** (same rule, recognisably the same shape) ·
**DIFFERENT-WAY** (same outcome, different mechanism — C# service / EF query / PG function /
worker instead of SQL/SP) · **PARTIAL** (some of the unit present) · **ABSENT** (nothing) ·
**DROPPED-BY-DECISION** (intentionally not carried over, with an in-code note).

> Scope note for Section A: the entire ASYCUDA sync in the rewrite is **one worker** that
> pulls **only the CusDec header** from Oracle and upserts it into Postgres. Items, taxes,
> containers, container statuses, status rows, inspections, inspection sections and payment
> summaries have Postgres **tables/entities** (`backend/src/Cdns.Domain/Entities/CusdecTables/`)
> but **no sync code writes to them**. Those units are therefore ABSENT as *sync logic* even
> though the destination table exists. This is stated once here and referenced per row.

Primary Section-A sources:
- `backend/src/Cdns.Worker/Worker.cs` (host/trigger/watermark)
- `backend/src/Cdns.Worker/Program.cs` (composition)
- `backend/src/Cdns.Infrastructure/ExternalServices/AsycudaSyncService.cs` (Oracle query + mapping)
- `backend/src/Cdns.Infrastructure/Sync/CusDecSyncProcessor.cs` (Postgres upsert)
- `backend/src/Cdns.Application/DTOs/Sync/CusDecSyncRow.cs` (row DTO)
- `backend/src/Cdns.Infrastructure/DependencyInjection.cs` (DI)
